# Eigen SparseLU threshold-zero validation

This is an uncommitted, benchmark-only validation of Eigen 3.4.0
`NaturalOrdering` with `setPivotThreshold(0.0)`. No production source or
default threshold was changed.

## Exact Eigen behavior

The audited source is Eigen 3.4.0 (`SparseLU_pivotL.h`, SHA-256
`5ad1a6b28183f605213c8987d9fe15dd17d57876dbc958210ec3ed0213306c5b`). For
each numerical column, `pivmax` is the largest magnitude candidate at or below
the current column. If `pivmax <= 0`, `pivotL()` returns a positive column
index; `SparseLU::factorize()` converts this to `NumericalIssue` and reports a
failed factorization. Otherwise it computes `thresh = u*pivmax`. With `u=0`,
every nonzero diagonal entry satisfies `abs(diag) >= thresh` and is accepted;
an exactly zero diagonal is not accepted, and the largest nonzero entry in the
column is selected instead. Thus threshold zero does not literally disable all
row permutation: it makes a nonzero diagonal preferred, while exact-zero
diagonals still use a row pivot. `info()` exposes `Success` or
`NumericalIssue`; a positive internal zero-column index is not exposed as a
stable public status beyond that failure state.

## Physical test design

The frequencies come from the local MINEOS PREM modal catalogues, rather than
from residual or pivot-displacement ranking: radial 0S0 (`0.8146635` mHz),
toroidal 0T2/0T12 (`0.3830516`/`1.881496` mHz), spheroidal 0S2/0S12
(`0.3108622`/`2.003070` mHz), and fluid-solid spheroidal 0S40 (`4.761725`
mHz). Each point is tested at the nearest ex3 production-grid frequency and
its two adjacent grid points (`df = 0.030517578125` mHz). Frequencies are
converted to the angular normalized units used by `FreqFull`; the ex3
240-minute `t_out` is passed as `t_out()/60 = 4` hours to that constructor, and
catalogue mHz values are never passed directly as `w`. The
systems use production-consistent NQ=6/maxstep=.05 dimensions radial 282,
toroidal 81, ordinary spheroidal 425, plus fluid-solid spheroidal NQ=6/step
.01 at dimension 1610. Both attenuation states and
the production epsilon `0.3229401443736645` plus `/10` and `/100` are
covered. Smaller values are
`0.032294014437366445` and `0.003229401443736645`, corresponding to the public `FreqFull` regularizer
obtained by tenfold and hundredfold longer time-series durations; they are not
the input `relative_error` field.

The RHS is generated by the SEM's production `calculateForceR`,
`calculateForceAllT`, and `calculateForceAll` machinery. Transfer checks use
the production receiver maps (`rvZR`, `rvBaseFullT`, and `rvBaseFull`) embedded
in the full-system coordinates. All available receiver rows/components and
RHS basis columns are retained; transfer magnitude is the dense infinity norm
of the projected contribution matrix. The LAPACK band solver is an independent
pivoted reference.

As a response-strength sanity check, the largest threshold-zero receiver
contribution in each family (across the three grid points and stress epsilons)
was `6.6113425875768247e-12` (radial 0S0), `1.9418173033548826e-14`
(toroidal 0T12), `7.0809905821586113e-14` (spheroidal 0S12), and
`2.6795015700125708e-13` (fluid-solid 0S40). These are actual source/receiver
projections, not residual-selection scores.

A threshold-one scan of only nine grid points around each catalogue root chose
the local physical grid peak before the final three-point test. The selected
centers were 0.823974609375 (radial 0S0), 0.3662109375 (toroidal 0T2),
1.8310546875 (toroidal 0T12), 0.30517578125 (spheroidal 0S2),
1.983642578125 (spheroidal 0S12), and 4.7607421875 (fluid-solid 0S40) mHz.
The scan is retained in `eigen_pivot0_validation_physical_peak_scan.tsv`;
the final rows test each selected center and its adjacent grid points.

## Result

The raw run contains 216 paired rows (108 per threshold). Every factorization,
solve, and LAPACK reference returned success and finite factors/solutions.
Threshold zero had zero nonidentity row pivots in all rows. Maximum values over
threshold-zero rows were:

| diagnostic | maximum |
| --- | ---: |
| normalized backward residual | `1.5270140987379321e-16` |
| relative solution difference vs threshold 1 | `1.0443773380094574e-7` |
| relative receiver-transfer difference vs threshold 1 | `4.832215365781625e-8` |
| relative solution difference vs LAPACK | `8.6274718093585e-8` |
| relative receiver-transfer difference vs LAPACK | `2.533225470948861e-8` |
| `max(|U|)/max(|A|)` | `0.6290736693462804` |
| `max |U|` | `5.5974721118918125e17` |
| `max |L|` off-diagonal multiplier | `5013.549795341349` |
| threshold-1 max `|L|` multiplier | `0.999999998013822` |
| threshold-0 / threshold-1 max-`|L|` ratio | `5013.549805299151` |
| max `|A|` | `8.898425323104026e17` |

The absolute U magnitudes reflect the physical matrix scaling, while the
off-diagonal L multiplier diagnostic is extracted from the supernodal dense
blocks (unit diagonal is implicit). The largest output discrepancy is about
0.10 ppm, and the worst threshold-zero result is sometimes closer to LAPACK
than threshold one; therefore output agreement alone does not uniquely indict
threshold zero. However, threshold zero generates an off-diagonal L multiplier
about 5,014 times larger than the threshold-one maximum (and just over 5,000 in
absolute value), violating the no-explosive-growth acceptance criterion. This
is a credible instability risk even with small final residuals, so threshold
zero **fails** this validation and must not be adopted.
The maximum L multiplier occurs for `spheroidal_0S12` at `2.01416015625` mHz,
attenuation on, epsilon `0.003229401443736645`. The largest solution
difference occurs for `radial_0S0` at `0.8544921875` mHz, epsilon
`0.032294014437366445`, attenuation on; the largest relative transfer
difference is for `spheroidal_0S2` at `0.30517578125` mHz, attenuation on,
with epsilon `0.003229401443736645`.
The production pilots were not run because the required robustness gate did
not pass.

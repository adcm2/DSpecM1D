Static Love Numbers

The optional Love-number module calculates dimensional static generalized loading and tidal responses for spherically symmetric, self-gravitating, radially transversely isotropic Earth models.

Overview

The calculated components are:

h_u k_u h_phi k_phi h_t k_t
h_load = h_u + h_phi
k_load = k_u + k_phi

Enabling The Module

The option defaults to OFF. Enable it when configuring DSpecM1D:

cmake -S . -B build \
  -DDSPECM1D_BUILD_LOVE_NUMBERS=ON

Command-Line Use

dspecm1d-love MODEL_FILE LMAX OUTPUT_FILE \
              [POLYNOMIAL_ORDER] [MAXIMUM_RADIAL_STEP]
  • The default polynomial order is 6.
  • The default maximum radial step is 0.01.
  • OUTPUT_FILE=- writes to standard output.
  • The polynomial order must satisfy p >= 3.

For example, calculate degrees 0 through 10 for the no-ocean PREM model:

dspecm1d-love data/models/prem.200.no.noatten.txt 10 love-numbers.txt

Output

Each degree produces one row with nine columns:

l h_u k_u h_phi k_phi h_load k_load h_t k_t
  • h_u, h_phi, h_load: m3 kg-1
  • k_u, k_phi, k_load: m4 kg-1 s-2
  • h_t: s2 m-1
  • k_t: dimensionless

Physical And Numerical Scope

  • The calculation is a static elastic, self-gravitating response.
  • Radial transverse isotropy and internal fluid regions are supported.
  • A surface ocean is not supported.
  • Degree zero uses the radial system.
  • Degree one uses the exact surface convention P(a) = 0.
  • Polynomial degree p uses p + 1 GLL nodes.
  • Background gravity uses the corrected shared MeshModel::Gravity implementation.

Validation

Validation includes analytic gravity and matrix tests, controlled all-solid and internal-fluid comparisons with gia3D, an isotropized PREM comparison, and an independent transversely isotropic comparison with ELLN. External codes are comparisons, not ground truth. GitHub CI exercises all 58 normal Love-number tests.

Library Testing

The main regression safety net is a suite of small, synthetic, local tests, with separate linked pages for each major test area and the heavier paper-reproduction workflows kept apart on purpose.

Testing Pages

  • Smoke and integration checks

  • Filtering, solver API, and SEM/component tests
  • Coverage status and residual risks

Test Categories

  • Unit: parser rules, quoted and unquoted values, range checking, helper functions, normalization, and file-format readers.
  • Component: output writers, filter option validation, and minimal SEM/local-to-global checks.
  • Smoke: CLI and C++ first-seismogram outputs, an installed-package consumer, the t1 tutorial, and the ex1 build check when their targets are enabled. Label: dspecm1d_smoke.
  • Migration and paper validation: optional reference comparisons are controlled by DSPECM1D_ENABLE_MIGRATION_TESTS and DSPECM1D_ENABLE_PAPER_VALIDATION; both are off by default.

Recommended Fast Developer Check

cmake -S . -B build/dev \
  -DDSPECM1D_BUILD_TESTS=ON \
  -DDSPECM1D_BUILD_TUTORIALS=ON \
  -DDSPECM1D_BUILD_BENCHMARKS=ON \
  -DDSPECM1D_BUILD_TOOLS=ON \
  -DDSPECM1D_ENABLE_SMOKE_TESTS=ON
cmake --build build/dev --parallel 2
ctest --test-dir build/dev --output-on-failure -L "unit|component"
ctest --test-dir build/dev --output-on-failure -L dspecm1d_smoke

Build options and inventory

These are the nine top-level project options and their defaults.

OptionDefaultEffect when enabled
DSPECM1D_BUILD_BENCHMARKSONBuild the programs in the benchmarks directory, including the paper examples.
DSPECM1D_BUILD_TUTORIALSONBuild tutorial programs.
DSPECM1D_BUILD_TOOLSONBuild command-line tools.
DSPECM1D_BUILD_TESTSOFFBuild the seven core test executables.
DSPECM1D_BUILD_LOVE_NUMBERSOFFBuild the optional static Love-number module and CLI; tests also require DSPECM1D_BUILD_TESTS.
DSPECM1D_ENABLE_SMOKE_TESTSOFFRegister lightweight executable smoke checks.
DSPECM1D_ENABLE_MIGRATION_TESTSOFFRegister temporary migration/reference comparisons.
DSPECM1D_ENABLE_PAPER_VALIDATIONOFFRegister paper and Love-number reference validation checks.
DSPECM1D_BUILD_DOCSOFFBuild the Doxygen and static website documentation targets.

The seven core executable targets are dspecm1d_parser_tests, dspecm1d_input_context_tests, dspecm1d_solver_api_tests, dspecm1d_output_writer_tests, dspecm1d_signal_filter_tests, dspecm1d_sem_component_tests, and dspecm1d_mesh_model_gravity_tests. Their discovered CTest cases carry both unit and component labels.

The optional Love-number suite adds dspecm1d_love_numbers_tests, dspecm1d_love_numbers_radial_state_tests, dspecm1d_love_numbers_dof_map_tests, dspecm1d_love_numbers_static_operator_tests, dspecm1d_love_numbers_static_fluid_tests, dspecm1d_love_numbers_static_solve_tests, dspecm1d_love_numbers_static_radial_tests, dspecm1d_love_numbers_static_degree_one_tests, dspecm1d_love_numbers_public_private_tests, and dspecm1d_love_numbers_cli_tests. Enabling paper validation additionally registers dspecm1d_love_numbers_reference_validation; see the Love-number guide.

Build a specific example or core test target with bounded parallelism:

cmake --build build/dev --target first_seismogram --parallel 2
cmake --build build/dev --target dspecm1d_solver_api_tests --parallel 2
ctest --test-dir build/dev -N
ctest --test-dir build/dev --output-on-failure -L "unit|component"
ctest --test-dir build/dev --output-on-failure -L dspecm1d_smoke

The CTest inventory is configuration-dependent; use ctest -N instead of relying on a fixed count. Optional migration checks use the migration/reference labels, core paper checks use validation/paper, and optional Love-number reference checks use paper-validation. Python plotting checks run in CI with python3 -m unittest discover -s tests -p "test_*.py" and require NumPy and Matplotlib in that Python environment.

Smoke-Test Safety

The smoke checks are configured to run serially where needed, with capped OpenMP thread counts and timeouts, so routine validation does not consume an uncontrolled number of CPU cores. For manual CLI, tutorial, or benchmark runs, set OMP_NUM_THREADS explicitly.

Coverage Summary

The self-contained suite now covers parsing behavior, InputParametersNew, preferred and legacy solver entry points, FilterOptions, filter validation, writer truncation and bounds behavior, reference-series readers, helper logic, and targeted SEM contracts.

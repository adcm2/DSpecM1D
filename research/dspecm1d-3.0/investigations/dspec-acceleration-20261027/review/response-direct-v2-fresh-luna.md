# Direct response reuse: fresh Luna review, v2

**Direct-path result: PASS, static review.** The prior v1 byte-accounting HOLD was incorrect and is superseded by this review. No build, SSH, or science run. Scope: direct response-cache reuse in `responses`, active symbolic reuse in `responses-symbolic`, and the shared field callback/audit hooks, compared with frozen `source-v6-tunya`. Global replay execution is excluded.

## Findings

- **Pass — cache footprint arithmetic.** Let `values = n * (forwardCols + basisCols)`. The cache stores four dense complex matrices: forward and basis RHS plus their two responses. Their combined storage is `32 * values` bytes. The two bit signatures store `2 * values + 4` 64-bit words, or `16 * values + 32` bytes. Total retained bytes are therefore `48 * values + 32`, exactly the estimator formula in `estimateBatchResponseFootprint()`. The example `n=10`, forward width 5, basis width 3 gives 3,872 bytes by both calculations. I retract v1's claim that preflight undercounts by 2×.
- **Pass — direct response reuse structure.** The key includes SEM identity, family, degree, and exact frequency bits; RHS bit signatures detect a changed forward or basis RHS. Baseline and kernel calls use the same active frequencies, and the kernel receives the cache only after a successful cached baseline. A weighted adjoint is represented in the exact receiver-row basis, reconstructed under the `1e-12` relative gate, then formed from cached Hermitian-adjoint unit responses. Nonfinite or rank-deficient cases fail closed. Static comparison found no sign/conjugation or DC/FFT/measurement-map change in the direct reuse branch.
- **Pass — cache-cap fallback.** Preflight rejection selects the original baseline path. A runtime `CapacityExceeded` clears and discards the partial cache, reruns the baseline without reuse, and calls the kernel without the cache. Partial responses are not consumed. `BasisMismatch` remains a failed run rather than a fallback, which is safe and should be reported as failure.
- **Pass — field callback and reconstruction audit.** The coefficient visitor emits records per element/radius and synthesis set; radial degree zero is emitted separately from the radial sampling result. The optional basis-residual pointer is reset per frequency and updated from exact receiver-basis construction for radial, spheroidal, and toroidal families. Spool serialization and global replay were not reviewed here.
- **Pass — symbolic reuse guard.** `DSPEC_SYMBOLIC_REUSE=1` opts into the accepted COLAMD backend only. It retains at most one solver per radial, spheroidal, and toroidal family per thread; equilibration and numerical factorization run every call. Symbolic reuse requires exact compressed dimensions and outer/inner index equality. The default `compute()` path and other solver backends remain unchanged.
- **Integration gate outside direct-path verdict.** `physical_driver.cpp` includes global spool types unconditionally, so the translation unit still depends on candidate-local global headers with `--response-record-spool off`. Synchronize those known-stale copies before building. The separately observed duplicate baseline in spool-mode control flow is a global execution issue and does not affect direct cache mode; it remains for the global-path review/fix.

## Gates for the planned direct phase

1. Keep the direct run's spool flag off and require metadata for reuse requested/used, preflight and runtime fallback, cache bytes, hits/misses, basis reconstruction residual, and symbolic analysis/reuse counts.
2. Treat basis mismatch, nonfinite response, or any failed numerical gate as a failed run rather than successful fallback.
3. Before any build, synchronize the candidate-local global headers; the off flag does not remove their compile-time inclusion.

# Direct response reuse: fresh Luna review

**Result: HOLD for the approved acceleration phase pending a preflight-accounting correction and integration gates below.** Static review only; no build, SSH, or science run. Scope reviewed: `responses` direct cache path and `responses-symbolic` active symbolic path against frozen `source-v6-tunya`. Global replay execution was excluded.

## Findings

- **Hold — cache preflight undercounts retained bytes.** `BatchResponseCache::getOrCompute()` accounts for four dense complex matrices (forward RHS, unit-basis RHS, forward response, unit-basis response) plus two exact bit signatures. That is 96 bytes per combined RHS value, plus fixed entry overhead. `estimateBatchResponseFootprint()` reports 48 bytes per value plus 32 bytes. The preflight can therefore admit a cache whose retained size is roughly twice the requested cap. The runtime check still rejects an over-cap insertion, clears the partial cache, and reruns the receiver-only baseline; this protects correctness, but can cause a late fallback and makes the preflight estimate/metadata misleading. Correct the estimate and add overflow-safe accumulation before relying on it for the planned run.
- **Pass, static — direct response reuse structure.** The cache key includes SEM identity, family, degree, and exact frequency bits; RHS bit signatures detect key reuse with changed forward or basis RHS. Baseline and kernel calls use the same active frequencies and the cache is only passed to the kernel after a successful cached baseline. On a hit, the weighted adjoint is formed by solving for its coefficients in the exact receiver-row basis and multiplying the cached Hermitian-adjoint unit responses. The relative reconstruction gate is `1e-12`; nonfinite or rank-deficient cases fail closed. I found no sign/conjugation or DC/FFT/measurement-map change in the direct reuse branch by source comparison.
- **Pass, static — capacity fallback is reference-safe.** A preflight rejection uses the original baseline path. A runtime `CapacityExceeded` clears and discards all entries, reruns the baseline without a cache, and later invokes the kernel without the cache. Partial responses are not consumed. `BasisMismatch` is not caught for fallback; it fails the run, which is safe but should remain an explicit failure gate rather than be reported as a completed fallback.
- **Pass, static — windowed-field callback and audit plumbing.** The new coefficient visitor emits records per element/radius and synthesis set; radial degree zero is emitted separately from the radial sampling result. The optional basis-residual pointer is initialized per frequency and updated from the exact receiver-basis construction for radial, spheroidal, and toroidal families. This review did not validate spool serialization or global replay.
- **Pass, static — active symbolic reuse guard.** The environment opt-in is exact (`DSPEC_SYMBOLIC_REUSE=1`), limited to the accepted COLAMD backend, and retains at most one solver per radial/spheroidal/toroidal family per thread. Each call re-equilibrates and refactorizes numerically; reuse requires identical compressed dimensions and outer/inner arrays. The ordinary `compute()` path remains intact, and no coefficient or pivot reuse is introduced.
- **Integration gate — candidate-local global headers.** `physical_driver.cpp` includes and compiles the global spool types unconditionally, even with `--response-record-spool off`. The known candidate-local header copy must be synchronized to the final global module before any build; disabling the flag does not remove this compile dependency. I did not inspect/rework global module behavior.
- **Metadata gate.** Confirm `response_cache_preflight_estimated_bytes` uses the corrected retained-byte formula and distinguish preflight ineligibility from runtime capacity fallback. A runtime fallback currently leaves the planned preflight estimate visible, which is useful only if the separate fallback flag stays authoritative.

## Gate criteria before short mathematical review

1. Correct footprint accounting to include the four dense matrices and two bit signatures (or conservatively overestimate), with checked integer arithmetic; align the cache cap/preflight decision with the exact byte counter.
2. Independently inspect the final synchronized global header copies for declaration compatibility only; keep the direct run’s spool flag off.
3. Keep the run metadata able to show `response_reuse_used`, preflight fallback, runtime capacity fallback, cache bytes, hits/misses, basis residual, and symbolic analysis/reuse counters. Treat any basis mismatch or nonfinite response as a failed run, not a successful fallback.

## Previous HOLD resolved

Format 2 prepends each pole and radial-L0 payload with three `uint64_t` fields: bin, native-side index, and slot. Whole-spool validation compares each payload identity against its position in the complete offset table before accepting its extent; `read()` repeats the identity check for all four payloads before returning them. Slots 0/1 distinguish forward and unit-adjoint pole records; slots 2/3 distinguish their L0 records. The writer's size estimate includes identities, record extents include them, and reader/writer both require magic `DSGSHSP2` plus version 2. A swapped offset now fails even when both payloads are otherwise valid and non-overlapping.

## Static checks

- The coefficient helper is present and its `lower_bound` precondition is enforced by writer and reader checks for unique, strictly ordered `(m,l)` labels. Degree/order limits and strain-array length are checked; the helper uses bounds-checked access and applies the fluid projection before rotation.
- Rotation matches the accepted prototype: Wigner upper index is local `m'`, lower index is global `m`; normalization is `sqrt((2l+1)/(4π))`; longitude phase is `exp(-i*m*longitude)`. Source and receiver use `frame.axes[2]` with no additional frame flip, matching the frozen code. Complex `qMix` is applied once to all unit-adjoint fields and separately once to the two adjoint L0 channels; the final values enter `pointKernel` through `adjointDualStrain`.
- The complete-band grid and transform API match the pinned source: `2L+1` Legendre nodes mapped by `acos(-x)`, `FastFFTSize(4L+1)` longitudes, declared band `L`, `nMax=2`, Generated Wigner values, Loop kernel, and the frozen `InverseTransformation(L, spin, input, Batch, output, Batch, Execution)` call shape. Same-spin batches use the accepted contiguous layout; fields are unpacked as contiguous channel arrays and the consumer writes the flat theta-major point prefix. The frozen prototype's low-L point/weight parity and reference comparisons remain the required runtime check; its own metadata says polar conventions are not runtime validated.
- Spool closure still requires forward and unit-adjoint pole records and both L0 records for each bin-side key, plus one unique audit per DC-inclusive bin. Writer and reader enforce audit index identity, finite complex `z`/mixing and nonnegative finite basis residual; the consumer applies the `1e-12` residual gate. Both kernel modes require DC inclusion, so the declared contiguous range starts at bin 0.
- Reader validation checks version, dimensions, overflow-safe header/table arithmetic, side/audit metadata, file bounds, payload lengths, non-overlap, and payload identity. The bounded validation-interval table is capped at 256 MiB.
- Working-memory accounting includes the side accumulator, 12 complex fields, frequency-result buffer, 12 coefficient arrays, two frame Wigners, one Generated-mode angular scratch estimate, low-degree batch scratch, reader metadata, a separate validation-table allowance, and a configurable transform scratch reserve defaulting to 2 GiB per worker. Generated scratch is estimated per working row rather than as a retained all-theta table. FFT longitude synthesis with the Loop backend is reported explicitly; no Eigen GEMM claim is made.
- Worker count is limited to 48, Eigen's internal pool is set to one, and each worker has independent reader, grid plan, output stream, and timing state. Contexts are constructed serially before worker launch. Partial thread-launch failure signals stop, joins all launched workers, and rethrows; worker exceptions are also propagated after joins. Timing aggregation occurs only after joins, avoiding races on each worker's plan and counters.
- Timing output separates serial worker-context setup, worker execution wall time, total consumer elapsed time, per-worker side elapsed time, and read/rotation/layout/inverse-FFT/contraction/frequency-add/write stage sums. The manifest explicitly says worker elapsed sums overlap in wall time and are not CPU time. No speedup claim is made.

## Small reporting notes

The spool preflight conservatively counts four L0 payload slots per key although the format stores two L0 payloads (forward and adjoint); this can reject a near-cap run unnecessarily but does not understate disk use. `total_wall_s` is sampled after worker output streams close but before manifest serialization, so it is consumer elapsed through output close rather than literally through function return. The main metadata reader's retained arrays are also present alongside the worker readers; the worker estimate counts each worker's retained metadata but does not separately add the main metadata reader. These are small accounting/reporting refinements to consider before measured resource claims; they do not reopen the v2 identity HOLD.

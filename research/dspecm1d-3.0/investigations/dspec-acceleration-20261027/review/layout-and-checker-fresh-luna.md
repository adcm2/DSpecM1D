# Fresh Luna High review: tensor layout, nodal recovery, and pair checker

2026-10-27. Independent, read-only source review of `packing-shared` and `nodal-shared` against the frozen Tunya source, plus static review of `tools/check_pair.py`. No SSH, build, or scientific execution was performed. Existing snapshots and `.orig` backups were left intact.

**Overall: HOLD the pair checker for Tunya comparison use until the listed audit gaps are fixed and reviewed.** The two candidate source deltas pass this bounded static parity review; that is not a compile or numerical PASS.

## Candidate source review: PASS, static only

- Packing deduplicates by a 64-bit hash bucket but confirms full vector equality before reusing a layout, so hash collisions cannot alias layouts (`candidates/packing-shared/engine_headers/Windowed3DFields.h:1761-1781`). The producer builds labels from ordered `std::map` entries and increasing degree (`source-v6-tunya/engine_headers/Windowed3DFields.h:1242-1249`), which supports the monotone permutation walk. Union keys are sorted/uniqued; the `l >= abs(spin)` mask matches the old component filter. Complex and real-degree paths keep the old key order, fluid projection, GEMM calls, phase multiplication, and accumulation order (`packing-shared/.../Windowed3DFields.h:1785-1805,1814-1882`). No duplicate-label or unsorted-label issue is apparent from the producer.
- Nodal recovery caches the same LTG lookups used by the old interpolation loops. The interpolation still sums nodes in ascending `q` order and applies the same shapes, derivatives, lift predicate, and field-family mapping (`candidates/nodal-shared/engine_headers/Windowed3DFields.h:366-422,424-455`). Toroidal lookup remains guarded by the solid/native domain, and consumers retain the corresponding skip conditions (`:381-387,1186-1188,1228-1235`). The byte-accounted fallback retains a local plan or uses the stack fallback when budgets are full (`:1140-1163`). The optional r-strain bridge only reuses node plans that the prior loop rebuilt at the same nodes; its interpolation and numerator arithmetic are unchanged (`:1174-1185,1218-1248`).
- These are source-level checks only. Before accepting execution results, keep the fixed `2e-13` channel/trace/spectrum gate and require byte equality for outputs whose arithmetic is unchanged. The checker currently makes byte equality optional via `--exact`.

## Pair checker: HOLD

1. **Recompute the energy identity from the underlying quantities.** `check_pair.py:117-122` trusts `energy_adjoint_relative_error_vs_2E` and only compares `energy_m2_s` and `energy_adjoint_qdotp` between jobs. Recalculate `abs(qdotp/(2*energy)-1)` for each result, compare it with the reported field, and enforce the existing `1e-10` gate.
2. **Compare the complete physical configuration.** `PHYSICAL` at `:12-17` omits material/model and domain-driving values written by `physical_driver.cpp`, including model length/time scales, mesh element/node counts, radial/spheroidal/toroidal DOF counts, source/receiver element IDs and fluid flags, `pole_only_nonradial_adjoint`, and `forward_only_baseline` (`source-v6-tunya/dspec/physical_driver.cpp:416-439`). Add every configuration field relevant to equivalence, while continuing to ignore timing-only fields.
3. **Validate each domain manifest internally, not only pair equality.** `:127-135` compares five domain fields between jobs and checks `actual_sampled_point_count * 6 * 8` bytes. It does not verify the declared point count against selected radial-side count × sampled-angle count, that sampled angles agree with `n_theta*n_phi` and completeness/subset declarations, or the full-target and actual binary byte fields. Validate these identities for each job and require its binary filename/layout and byte declarations to agree with the receipt and file.
4. **Bind native side/material identity to the selected kernel domain.** Exact pair equality of `radial_nodes.csv` and `kernel_radial_nodes.csv` at `:136-149` is useful, but the checker does not validate row counts/IDs/material flags against each job's `selected_radial_trace_count` or confirm that kernel radial rows are the intended subset of that job's native side table. Add those per-job cross-checks so two identically wrong manifests cannot pass.
5. **Make exactness an explicit gate for these unchanged-arithmetic candidates.** `--exact` defaults off (`:109,171-179`); the candidate changes above preserve coefficient ordering and summation sequence. Require byte equality for the compared result arrays for these routes, or record a reviewed per-artifact exactness policy. Keep `2e-13` as the numeric gate and do not relax it.

The before/after completed-job evidence check does compare the complete job object and its verified output/log digests (`:157-159`), and the tool has no job-launch path. Those checks do not cover the per-job physical/domain consistency gaps above.

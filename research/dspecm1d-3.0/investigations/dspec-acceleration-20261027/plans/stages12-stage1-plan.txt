3. Timing model: wall time and worker sums are different quantities

Use steady_clock and existing mathprofile nested Scope inclusive/exclusive
nanoseconds. Its thread_local maps and WorkerCapture already save/restore master
state and merge worker durations under parallel_worker.*. Keep auditprofile
disabled with DSFAST_DISABLE_PROFILE in EVERY variant: its global maps are not
safe for worker recording and its inclusive seconds do not establish exclusivity.
Native build retains MATHPROFILE_DISABLED. Profile build removes only that flag.
Do not enable FTZ, change -O3/GCC/BLAS, alter symbolic reuse or caching, add a
frequency parallel region, change schedules, or change arithmetic expressions.

Add a driver pipeline scope covering setup through existing output completion;
its lifecycle must end before Root serialization, while original result.json
timing semantics remain intact. The profile-enabled path may take cumulative
Entry/counter snapshots only after all workers joined and phase scopes closed.
Difference adjacent snapshots for setup/initial/measurement/kernel/output groups;
retain raw cumulative MATHPROFILE output too. Account snapshot/report overhead in
its own wall bucket; never clear maps beneath a live scope or Root. Profile-only
snapshot code compiles out of native mode. Keep a fixed-size35 per-frequency
coarse wall array if helpful; write it once after the scientific output. No
per-point clocks, per-element logs or per-frequency profile JSON serialization.
Exclude diagnostic tensor validation from kernel production groups using an
explicit diagnostic parent scope and snapshots/deltas around that closed scope,
including its nested timer deltas. Its scopes must not contaminate production
radial/synthesis totals. Preserve validation's effect on subsequent cache state.

Important parallel accounting rule: exclusive wall partition comprises serial
master scopes plus a named parallel-degree-region wall bucket. Time that bucket
around the current OpenMP launch through join; separately time ordered result
collection/profile merge. Sum of worker assembly/factor/solve exclusive durations
is elapsed worker time, not exclusive wall time or CPU time. These quantities
overlap the parallel-region wall bucket and MUST NOT be added to wall totals or
divided by8 and relabelled wall time. Existing master modal exclusive time
otherwise silently contains the parallel block. With1worker the same operations
are serial and may be reported as serial wall components. The truthful8worker
report exposes this irreducible mixed parallel wall block and its worker-side
breakdown; it must not invent disjoint per-operation wall contributions for
simultaneously running different worker operations.

Every table row has: phase, scope_name, execution_domain(master_wall or
worker_elapsed_sum), inclusive_s, exclusive_s, calls, logical_component,
diagnostic(boolean), and parent/overlap description. Include run/binary/source/
input hashes, compiler flags, worker count, selected backend, machine affinity,
environment, profiler variant, elapsed_s and external process wall/resource
receipt. Raw output and aggregate tables retain all names and counters; unknown
names remain visible under unclassified rather than being discarded. No sum of
inclusive rows is a total. Materially overlapping reported scopes have explicit
labels. Native speed comparisons use native elapsed/process times only.

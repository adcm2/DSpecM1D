Models and output formats

The solver reads Minos/MINEOS model decks, converts their material values to internal nondimensional units, and writes text traces, snapshots and kernels; optional sampled volume kernels use NetCDF.

{{REVISION_NOTICE}}

Model decks

model names a Minos/MINEOS deck in SI units. The parser accepts the six-column isotropic form (radius, density, P and S wave speeds, bulk and shear quality factors) and the nine-column transversely isotropic form (radius, density, Vpv, Vsv, Qκ, Qμ, Vph, Vsh, η). The bundled PREM deck is a nine-column example. Header metadata and repeated radii describe the layer boundaries; preserve deck ordering and discontinuities when preparing a model.

Each layer's properties are represented by natural cubic splines through its knots. Consecutive layers of the same phase form a region. Gravity follows from the density profile. The solver and Model use nondimensional quantities internally; the public model API exposes scales for conversion to and from SI.

Discontinuities and sides

Layer boundaries are retained, including repeated-radius one-sided values. The C++ model lookup API accepts YSpec::Side::Below or YSpec::Side::Above; its default is Below. A source or receiver exactly on a solid–fluid boundary is interpreted on the solid side by the radial solver. Every source in one calculation must be in the same solid region. Receivers and snapshot points may be in a fluid or core but cannot be at the centre. See RadialSolver's boundary contract and Model::LayerIndex.

Seismogram files

For one source, outputs are <prefix>.1, <prefix>.2, and so on in receiver order. For multiple sources with names, outputs are <prefix>.<name>.1 and so on; unnamed sources use their sequence numbers. Each row has four whitespace-separated columns: time after origin (s), vertical up, north and east. Without an instrument, components use the selected displacement (m), velocity (m/s) or acceleration (m/s²) quantity. With a SAC pole-zero instrument, values are in that instrument response’s output units; they are not necessarily counts.

Each seismogram run also writes <prefix>.receivers. Its header is file source latitude longitude depth_km distance_deg azimuth_deg back_azimuth_deg; rows are source-major and receiver-minor. Latitude/longitude, distance and azimuths are degrees, and receiver depth is km. Receiver ordering is group by group; within each group, depths are traversed in order, and every location is emitted at each depth. Snapshot components instead follow up, away along the source great circle, and transverse (90° anticlockwise from away viewed from above). Snapshot rows also save geographic latitude and longitude; map plots use these coordinates rather than reconstructing positions from distance and azimuth.

Snapshot files

One file is written per source and requested time, numbered in time order; named sources appear in the filename only when there are several sources. Two comment lines precede the data. Each row contains depth (km), distance and azimuth from source (degrees), latitude, longitude, then up, away and transverse values. Grid iteration order is depth, azimuth, distance. The grid is shared in each source's local frame. The three components use the selected output quantity: displacement (m), velocity (m/s) or acceleration (m/s²), matching the seismogram quantity selection.

See WriteSnapshots for the public writer contract and a small checked snapshot command.

Kernel outputs

For one measurement, files use the output prefix and suffix directly: .measurement, .kernels, and, when requested, .sections, .maps and .nc. For several measurements, the measurement name is inserted after the prefix. Unnamed measurements use their input-order number.

The .measurement file has columns time_s, the selected seismogram component, the window function and the adjoint-source sample. Time is seconds; the seismogram uses the selected quantity units (m, m/s or m/s² without an instrument, otherwise instrument output units); the window is dimensionless. The adjoint-source units follow the measurement units divided by signal units and seconds.

The radial .kernels header lists parameter columns after radius_km depth_km weight_m3. Its # at_source row records point terms PX at the source radius. The integral weights approximate r²dr; for absolute scaling, the represented sensitivity is the weighted radial integral of KX δX plus PX δX at the source. There K has units s m−3 per unit X and P has units s per unit X. X uses SI units: density kg m−3, velocities m s−1, elastic moduli Pa, and η and inverse-Q parameters dimensionless. For relative scaling, the perturbation is δln X, K has units s m−3, and P has units s. The radial density kernel depends on the selected parameter set: density is perturbed at fixed moduli for love and moduli, at fixed velocities for velocities, and at fixed velocities and η for anisotropic. The resulting equilibrium-gravity change is included.

Section and map rows contain an optional section tag, layer index, depth (km), along-path and across-path coordinates (degrees), latitude and longitude (degrees), then the named parameter kernels. The sections file tags its two grids path and across; each map row has no section tag. Rows are written by radial node, then in the sampled lateral-grid order. Their header gives kernel units: per unit volume, in s m−3, with a further per-unit-X factor for absolute scaling; relative scaling uses log-X perturbations. Plot colour limits are display clipping only and do not alter these saved values. Sampled 3D outputs are only elastic-parameter and inverse-Q sensitivities at fixed density; they intentionally do not contain a density kernel. For the velocity parameter set, radial columns are rho vp vs qkappa qmu, while sampled columns omit rho. The radial source-point term P_X is concentrated at the source and cannot be represented by a sampled grid; the sampled 3D files contain the continuous fields and omit this term. They therefore do not alone give the full sensitivity including that point contribution. See the sampled-kernel API contract and derivation.

Requesting kernels.volume writes a planetmodel NetCDF model file. It records layer bounds and interfaces at the root; sampled fields use radial-node and latitude/longitude dimensions, with separate pole values and coordinate metadata. Fields include names such as K_vs, K_vp, K_qmu and K_qkappa. Units depend on parameter and absolute/relative scaling and are stored with the field metadata. Volume writing requires a C++ build configured with the default-on YSPEC_WITH_NETCDF=ON option and NetCDF-C; the Python package disables volume writing. Sections and maps remain available without NetCDF. See the kernel guide and plotting commands.

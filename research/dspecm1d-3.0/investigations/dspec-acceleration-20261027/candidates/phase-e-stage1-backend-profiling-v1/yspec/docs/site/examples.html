Small snapshot grid · CLI

This fixture reuses the bundled PREM deck but asks for only one time, one depth, two distances and two azimuths. It is intended to verify the output format, not model convergence.

mkdir -p build/snapshot-small
cp docs/site/examples/snapshot-small.json build/snapshot-small/input.json
cp examples/prem.200 build/snapshot-small/prem.200
OMP_NUM_THREADS=2 build/guide/bin/yspec-snapshot build/snapshot-small/input.json
wc -l build/snapshot-small/snapshot.1
head -n 4 build/snapshot-small/snapshot.1

The output begins with two comment rows followed by four rows (one per distance/azimuth pair). This single-source output uses snapshot.1 even though the fixture names the source; source names are added to filenames only when a calculation has several sources. The accompanying downloadable JSON is the exact fixture used in the check. Read the snapshot column and ordering definition.

Several sources, receiver depths, profiles and an instrument · CLI

This complete small input combines two differently named sources at the same depth, two receiver depths, a two-point great-circle profile and a SAC pole-zero instrument. Both sources are in the same solid region. The outputs include four receiver traces for each named source:

mkdir -p build/workflows
cp docs/site/examples/workflows.json build/workflows/input.json
cp docs/site/examples/station.pz build/workflows/station.pz
cp examples/prem.200 build/workflows/prem.200
OMP_NUM_THREADS=2 build/guide/bin/yspec build/workflows/input.json
ls build/workflows/multi.event-a.* build/workflows/multi.event-b.*

These downloaded input and instrument files are the exact pair checked by the documented run. The input parser tests cover each of these forms independently as well.

Strain and radial kernels · C++ library

The strain trace remains a library workflow; yspec-kernels also exposes its restricted cross-correlation traveltime workflow through JSON. The short compilable C++ consumer computes one radial strain trace, forms a cross-correlation traveltime measurement, and evaluates radial density kernels with a reduced mesh:

g++-13 -std=c++23 -O3 -I. docs/site/examples/library-workflows.cpp \
  build/guide/libYSpec.a -lfftw3 -lfftw3f -lfftw3l -fopenmp \
  -o build/guide/bin/library-workflows
OMP_NUM_THREADS=2 build/guide/bin/library-workflows examples/prem.200

The high-level objects use SI units. Strain components are rr, tt, pp, rt, rp and tp in the local spherical frame; rt and rp are zero in fluids. Radial kernels use the parameters ρ, A, C, F, L, N, qA, qF and qMu: density is perturbed at fixed moduli while including its resulting equilibrium-gravity change; moduli are perturbed at fixed density; qA, qF and qMu are the model's inverse quality factors for A/C, F and L/N. The radial integral uses quadrature weights for r²dr (m³), with a separate source-point term PXδX(rs) where present. For a moment tensor, point terms occur for C, F, L and their associated inverse-Q kernels. In fluids, only isotropy-preserving A/C/F and qA/qF combinations have meaning; L/N-related kernels are zero. The adjoint receiver must be in the forward source's solid region, and potential-and-tilt-corrected measurements are unsupported. Current tests compare measurement changes with finite differences, not a universal inverse-problem accuracy guarantee. See ComputeStrains, ComputeRadialKernels and the derivation.

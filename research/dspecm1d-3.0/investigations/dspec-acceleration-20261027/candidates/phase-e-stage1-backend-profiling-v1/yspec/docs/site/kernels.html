Examples

Traveltime kernels

The yspec-kernels program computes adjoint kernels for cross-correlation traveltimes measured on one source's seismogram at one receiver.

{{REVISION_NOTICE}}

Build and run the bounded input

The standard CMake option defaults to YSPEC_WITH_NETCDF=ON; install the NetCDF-C development library before configuring, or set the option OFF for sections/maps-only builds. Configure three programs and build the kernel executable with a two-job cap. From the repository root:

cmake -S . -B build/kernels -DCMAKE_CXX_COMPILER=g++-13 \
  -DCMAKE_BUILD_TYPE=Release -DYSPEC_BUILD_TESTS=OFF
cmake --build build/kernels --target yspec-kernels --parallel 2
mkdir -p build/kernel-small
cp docs/site/examples/kernels-small.json build/kernel-small/input.json
cp examples/prem.200 build/kernel-small/prem.200
OMP_NUM_THREADS=2 build/kernels/bin/yspec-kernels build/kernel-small/input.json
ls build/kernel-small/kernel-small.*

The exact small input fixture requests relative velocity kernels for a named T-component mixed shear packet over 1000–1200 s, with sampled path sections and maps. It uses degrees through 200, 2–10 mHz with a [2, 4, 8, 10] mHz taper, and a 40-minute record at 2 s. At the fixture’s 60° geometry, PREM TauP predicts S, sS and ScS at 1093.838, 1108.787 and 1190.905 s, all within the window; shear-packet is a target label, not a phase-isolation claim. The current C++ run completed in 13.08 s with two OpenMP threads and saved 1,201 samples from 0 to 2,400 s at 2 s intervals; that timing is environment-specific. This bounded rendering fixture is not a converged sensitivity result. More generally, TauP ray times locate windows but do not establish that a finite-frequency packet contains only one phase. The input and model paths resolve relative to the JSON file.

The program writes radial kernels, per-measurement seismogram/window/adjoint-source data and, when requested, sections and maps. Volume output is opt-in. The separate 20-minute volume example is an execution-only smoke test, not a phase measurement or a figure source.

Input limits and choices

The strict JSON parser accepts exactly one source, one receiver and at least one measurement. Names are optional; unnamed measurements are numbered in input order, while supplied names must be unique and may not contain a slash. Each measurement selects component Z, N, E, R or T and a traveltime object with window_s: [start, end] and optional taper_s. The window must lie within the time series and have positive length; the taper is between zero and half the window. Unknown members are errors. The ordinary seismogram JSON accepts multiple sources and receiver groups, so do not assume its full schema applies here.

Kernel options include parameterizations love, moduli, velocities (default) and anisotropic; scaling absolute (default) or relative; and an optional quadrature mesh. Optional sections default to 15° margin, 15° half-width, 0.2° spacing and 25 km radial spacing. Maps require depths in km and default to 10° margin, 15° half-width and 0.5° spacing. A volume request defaults to degree 64 and maximum radial element length 100 km; its setting overrides the spherical degree and maximum element length used for the NetCDF grid. All lengths ending in _km are kilometres, frequencies in the shared input are mHz, and time fields ending in _s are seconds. See the fixture and the input reference.

Output and NetCDF boundary

Radial parameter kernels are written to <prefix>.kernels; each measurement also receives its measurement record and any requested sampled outputs. With multiple measurements, their names are inserted after the prefix before each suffix. Sections and maps are text outputs and work without NetCDF. The YSPEC_WITH_NETCDF CMake option defaults to ON and requires NetCDF-C during configuration; use -DYSPEC_WITH_NETCDF=OFF for a sections/maps-only build. Writing the through-earth volume requires the enabled option. The separate volume fixture is an execution-only smoke test for the optional request, not a phase measurement or figure source:

cp docs/site/examples/kernels-volume-small.json build/kernel-small/volume.json
OMP_NUM_THREADS=2 build/kernels/bin/yspec-kernels build/kernel-small/volume.json

The Python package build explicitly disables NetCDF and cannot write this file. Its plotting extra can read NetCDF files produced by the C++ program. A sampled section/map run does not require the volume option. Absolute kernel units include the SI unit of the parameter: density in kg m−3, velocities in m s−1, elastic moduli in Pa, and η and inverse-Q parameters dimensionless. Relative kernels are with respect to δln X. Plot bars state the units and display limit; clipping affects colours only. For plot scales and file interpretation, see plotting and model and output formats.

Interpretation boundary

Radial kernels include density sensitivity, and the perturbation held fixed depends on the selected parameter set: moduli for love or moduli, velocities for velocities, and velocities plus η for anisotropic. The resulting equilibrium-gravity change is included. The sampled 3D sections, maps and volume contain elastic-parameter and inverse-Q kernels at fixed density; they do not contain a 3D density kernel. In the bounded velocity-set fixture, the radial table has rho, vp, vs, qkappa and qmu columns, while sampled outputs contain vp, vs, qkappa and qmu. Other parameter sets change these names. The radial P_X source-point term has no representation on the sampled 3D grids: the 3D files contain sampled continuous fields and omit this concentrated contribution, so they do not by themselves represent the full sensitivity including the source-point term. See the sampled-kernel API contract and derivation. Kernel parameterization, scaling, mesh, selected component, window and model all affect the output. Existing tests include finite-difference checks and volume-file checks, but they do not establish convergence or accuracy for arbitrary models and input settings.

The README radial-kernel example named S uses a 1000–1200 s window; at its 60° PREM geometry, direct S, sS and ScS arrivals fall in that interval. Its kernel is a mixed transverse packet unless separate waveform evidence justifies a narrower phase interpretation. The long-period vertical window is named long-period-Z-packet; no surface-wave dispersion, normal-mode or group-velocity comparison validates it as Rayleigh. Its identification and numerical convergence remain unresolved. The measured windows, arrivals, raw outputs and unresolved convergence limits are listed in the plot status and provenance record.

For C++ library-level control, see the library guide.

The public C++ entry points are ReadKernelInput (parse the JSON request), RunKernels (run and write radial results), and ComputeSampledKernels (compute sampled 3D fields). The CLI combines these steps; library callers can use them directly.

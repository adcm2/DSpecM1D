# Combined DSpec acceleration candidate status

Base: completed response and symbolic-reuse candidate, itself based on the exact 12-file DSpec source-v6-tunya tree.
Scope: shared baseline responses, guarded symbolic reuse, packing-shared coefficient layouts, nodal-shared SEM recovery, and compact response-spool/global GSH execution. No receiver lifting, Sobolev formulation, library-degree changes, figures, builds, or science runs.

- **Bounded shared response path** in `physical_driver.cpp`: kernel modes can pass one `BatchResponseCache` through the physical baseline and kernel stages. The baseline captures the forward response and exact receiver-row unit-adjoint basis using the same per-frequency equilibrated SparseLU factor; after the waveform determines `q`, the kernel stage reconstructs the weighted Hermitian adjoint from that basis and reuses the forward response. The default cache cap is 32 GiB, configurable with `--response-cache-gib`; the exact preflight computes entry count, retained dense matrix/signature bytes, and maximum DOF count from every active family/degree and receiver basis, then sizes the entry limit to that frequency-degree set. If preflight exceeds the requested cap, the candidate runs the original path and reports that reuse was ineligible. An unexpected runtime cap still clears and restarts baseline without reuse. `--response-reuse off` preserves the no-acceleration reference route. This path retains existing source lifts, interface-side semantics, damping, DC, FFT and measurement mapping. Static review only; no build or scientific run.
- The physical result metadata now records requested/used reuse, capacity fallback, cache entries/bytes/hits/misses, maximum unit-basis reconstruction residual, and whether baseline really ran forward-only. The JSON and `MATHPROFILE` counters are intended to let later Tunya runs distinguish factor/RHS work and cache outcomes.
- **Compact in-pass record callback**: `baseline()` can now accept a per-frequency record sink. When enabled it solves with unit vertical receiver weight, obtains the physical baseline displacement from the same frequency workspace, then emits the workspace's existing `PoleAngularCoefficientRecord3D` records for every native radial side plus the receiver suffix. This includes source set 0, weighted/unit adjoint set 1, and the separate forward/adjoint radial-L0 records, without retaining sparse factors or repeating a modal solve. The sink receives each bin and record; radial side identity is resolved from element and exact radius against the written native-side table. No spool format is duplicated here; global candidate owns serialization. Static source review only.
- Added the maximum exact receiver-row-basis reconstruction residual to the existing basis helper and threaded an optional audit pointer through frequency-workspace preparation. This supplies the compact spool's per-frequency residual without approximating it as zero.
- **Tunya-sized cache preflight**: `--response-cache-gib` now defaults to 32 GiB. A new exact footprint pass mirrors the active source RHS widths and exact receiver-basis widths over the selected radial/spheroidal/toroidal degrees, then scales by baseline frequency count. It reports estimated bytes, entries, and largest DOF count, sizes the entry cap to the estimate, and skips reuse before any solves if the cap is insufficient. Runtime capacity fallback remains guarded and reported. This is meant for independent attribution on the direct tensor path.
- **Optional compact response spool/global replay**: `--response-record-spool on` captures all native radial sides with one unit vertical adjoint solve per frequency, writes the exact engine coefficient records through the candidate spool format, adds per-bin frequency/q-mix/basis-residual audits after energy is known, and invokes the no-solve global consumer. It requires kernel mode, contacts off, and all native radial sides (`--radial-traces 0`). The imported `global/` headers are a candidate-local copy aligned to this exact engine tree; source/global candidates remain untouched. Spool cap defaults to 128 GiB via `--response-spool-gib`, and full or prefix-angle consumption is controlled by existing mode/options. Static-only; no build or science run.

Static-only; no build or science run.

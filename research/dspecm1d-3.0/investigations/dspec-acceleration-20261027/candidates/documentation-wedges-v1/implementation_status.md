## Cache-policy exploration carried forward from combined-cache-v1

- Copied the reviewed combined-v3 candidate into a new directory; prior candidates remain unchanged. Added `--global-wigner-storage generated|stored` (default `generated`). The `stored` policy uses the pinned GSHTrans immutable shared grid implementation (`shared_ptr<const Impl>`) once per consumer and shares that read-only basis among worker plans; transform scratch and FFTW plan caches remain thread-local.
- Added the exact full-table extent estimate for this grid: `(2L+1) * (5*(L+1)^2 - 10) * sizeof(double)` for `n=-2..2` and all orders. At L=1536 this is 290,382,151,640 bytes (about 270.4 GiB). The table is charged once as shared working memory, not replicated per worker. Per-worker bounds include two frame Wigner objects, cached phase/norm arrays, transform and coefficient buffers, selected same-spin batch scratch, the complete side accumulator, reader metadata, and the configured transform reserve.
- Same-spin batching remains four channels at L<=32; at higher degree it selects two only when the configured memory budget can fit one such worker after shared-table and spool-validation allocations, otherwise it uses single-channel transforms. Batch selection and its scratch bytes are recorded in the output manifest.
- Each worker plan keeps per-frame longitude phase and normalization arrays beside the Wigner frame cache. Evaluation retains the existing multiply/divide/sum/phase operation order; phase and norm values are evaluated once per distinct frame and reused across frequencies and channels. The additional storage is two `(L+1)^2` complex phase tables plus two `(L+1)` real norm arrays per worker.
- The manifest records shared Wigner bytes, per-worker estimates, total estimated working bytes, selected batch size, and serial grid/context construction duration. GSHTrans/FFTW plans initialize lazily in each worker's first inverse transform; this cost remains inside that worker's first inverse/FFT duration, not the serial constructor timer.
- Source-only design candidate; no build, Tunya access, numerical run, or performance evidence. Independent review and parent-owned resource/throughput validation are required.

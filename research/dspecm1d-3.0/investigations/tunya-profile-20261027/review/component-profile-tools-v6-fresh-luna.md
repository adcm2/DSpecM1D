## Bounded caveats

The collector trusts the receipt path keys it is given: its initial manifest loop joins each key to the snapshot root without rejecting absolute keys or `..`. The reviewed finalizer creates only safe relative keys and is the intended producer, so the reviewed workflow does not generate such a manifest; direct collector use should be limited to trusted finalizer snapshots. Also, the finalizer enforces exact job IDs, but does not itself compare saved commands against configs-v8 or gate actual-degree/probe-angle metadata against each job label. For the 23 commands currently present, I checked the saved commands/cwds against configs-v8 directly; the remaining three jobs were pending in this snapshot. The final report should retain the snapshot state and plan hash for review of those completed commands. The current partial snapshot cannot establish their results or command agreement.

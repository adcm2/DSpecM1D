# Fresh Luna review: detached prerequisite waiter

**Verdict: HOLD for launch until the build receipt is bound to the exact executables in the reviewed plan.** This was a read-only static review of `tools/wait_and_launch.py`, the README CLI description, the v3 plan, the build receipt format, and transfer verification writer. I did not launch the helper or supervisor, run mock tests, build, calculate, or use SSH.

The ordering is otherwise conservative: the helper requires absolute roots and valid SHA-256 arguments, waits at most four hours, stops on terminal or malformed build state, requires a verified-transfer marker, then checks the expected checker and plan hashes. It validates a completed seven-variant receipt, hashes each receipt-named binary, checks that each binary is inside its variant directory, verifies the campaign root, and refuses an existing task ID before `exec`-ing the supervisor. The supervisor’s campaign-wide nonblocking lock provides a second guard against two concurrent launches.

The blocker is that `verify_build_receipt()` trusts `build_root` from the receipt and never compares the seven verified binary paths with the executable paths in the reviewed plan. It also does not bind that build root to the reviewed build-03 configuration. The v3 plan launches binaries from the configured `...kernel-profile-20261027-03/{variant}/...` paths, while the waiter only proves that *some* seven binaries named by the receipt have the recorded hashes. A stale or mismatched receipt could therefore pass its hash checks while the plan points at different binaries. Require exact path correspondence between each receipt output and its plan executable/input, and bind the receipt root to the reviewed build root before launch.

There is also a small fail-closed availability race: `extract_on_tunya.py` creates `transfer-verification.json` with exclusive open and then writes the JSON incrementally. If the waiter polls during that short write window, `read_json()` raises and the detached waiter exits instead of continuing to wait. This cannot launch early, but it can require a manual restart. Consider treating a temporarily unreadable transfer report as pending until the deadline while continuing to fail on a readable non-`verified` status.

The documented CLI and four-hour behavior match the implementation. The helper leaves task and campaign output creation to the final supervisor `exec`; its own stdout/stderr logging is supplied by the operator’s detached launch command. The above receipt-to-plan mismatch remains a launch gate.

## Interim verdict

The campaign has meaningful exact alternatives, but acceptance remains path-specific. The copied-engine smoke checks are not historical-production acceptance. The v4 tensor implementation reconstructs its angular plan on every tensor synthesis call; therefore its tensor-route timings cannot demonstrate persistent angular-plan reuse. Parent has independently identified this and asked implementation to freeze a v5 plan while retaining v4. The v4 fast binary remains a valid frozen reference for the old implementation.

The frozen comparison evidence currently available supports the ordinary contact-enabled, batch-disabled tensor-real route for the listed L3/L6/L12, frequency, angle-grid cases. The batch-response route is volume/spectrum/objective qualified only; near-zero contact errors cross the unchanged 1e-12 gate. Source inspection confirms there is no contacts-on fallback: when batch mode is enabled, the workspace and its contact calculation both consume the reconstructed weighted adjoint. Native-grid L3 passed in the listed case; L12/F3 native kernels fail the strict gate for both physical-derivative and Dref/J branches. The solver alternatives band LU, NaturalOrdering SparseLU, and static condensation remain rejected by existing field/contact gates despite small original-system residuals. Do not erase or relabel these failures.

## Code findings

1. **Tensor angular-plan rebuild in v4 (performance claim blocker, not an observed numerical error).** `sampleForKernelsTensor` constructs a fresh `CachedAngularWigner` for each `synthesisOne` call and creates complex/real angular basis matrices within each component/order contraction loop. This path uses `SamplingPlanCache` to extract representative radial coefficient records, but the main tensor GEMMs do not reuse a persistent Wigner/basis plan. Rebuilding occurs across frequency/objective calls and per receiver synthesis set. Thus v4 may be compared numerically, but timings must include this setup and cannot be presented as the persistent tensor-plan result. The new v5 needs its own freeze/hash, full correctness recheck, and timing comparison.

2. **Sampling-plan 32 MiB is a payload accounting cap, not a hard retained-memory bound.** `SamplingPlanCache::bytes` counts principal vector/matrix payloads but not map node/allocator overhead or the large vector keys. `packedBases` keys copy the angular coordinates and coefficient labels; angular cache maps also retain copied angular keys. Report the value as accounted payload, or measure process/allocator memory if a hard memory bound is claimed.

3. **Batch-cache 512 MiB is retained-payload accounting, not peak-memory accounting.** `BatchResponseCache::retainedBytes()` counts matrix payloads and exact uint64 RHS signatures but not map/entry allocation overhead. `Result` returns Eigen matrices by value, so cache hits and downstream locals make deep copies; peak memory can exceed retained payload. Its one-driver lifetime, exact SEM-address/family/degree/frequency key, exact forward/unit-RHS signatures, and un-floored <=1e-12 RHS span check are appropriate under the stated immutable-SEM contract. The key itself does not fingerprint a mutable operator, which is acceptable only with that lifetime/immutability constraint.

4. **End-to-end route versus helper-only distinctions are mostly documented correctly.** v4 routes scalar/Eigen/OpenBLAS packed contractions and complex/real-degree tensor contractions through actual solver-derived coefficients and the normal kernel/contact/objective routines. Batch response reconstruction is actual but opt-in. The pair covariance/evaluation, relative-spin product, symbolic-pattern comparison, and shared-factor wrapper in `fast_engine.hpp` are helpers, not integrated candidate routes. Frequency covariance and harmonic/FFT processing are in the separate spectral consumer; they validate volume outputs and do not include accepted source-contact behavior.

5. **Native derivative/r*strain bridge scope must remain narrow.** The explicit SEM Dref/J node derivative and physical-coordinate derivative branches are separately selectable. The r*strain interpolation bridge is a genuine alternative in the copied engine and agrees with its direct route in same-engine smoke, but that alone does not establish frozen-production equivalence. Frozen native-grid comparisons are degree-sensitive: the reported L3 case passes, while L12/F3 exceeds the strict kernel L2 gate for both derivative branches. Do not present it as generally accepted from the low-degree smoke.

2. **Batch contact path has no automatic direct-solve fallback.** `driver.cpp` passes the cache pointer whenever `DSFAST_BATCH_RESPONSES=1`, without conditioning it on `DSFAST_CONTACTS`; `sourceShellContact` evaluates from that same workspace. Therefore the contacts-on failures are real failed comparisons, not cases where code retained the direct weighted-adjoint path.

3. **Tensor permutation handling.** `sampleForKernelsTensor` maps exact angle and trace keys and restores outputs through per-trace point maps. A fully permuted complete Cartesian product is accepted; duplicate angles or ragged/incomplete products are rejected.

## Mathematical review summary

The exact frequency-first coefficient identity is implemented in helper/consumer form as `C = A^H F`, retaining only same-frequency products while preserving all angular degree/order cross terms. The complex SVD right factor and output-verified numerical-rank scan are present; no singular-value-only truncation is used. The scalar harmonic recoupling uses the documented convention-safe projection and the global FFT is gated on tensor completeness and sufficient resolution. The reported all-trace L3/L6/L12 packet checks show field/covariance/Gaunt/FFT agreement within stated numerical tolerances, but this is independent volume spectral evidence, not whole-engine field/contact acceptance or physical convergence.

The receiver-row basis reconstruction is algebraically sound: selected receiver rows are conjugate-transposed into basis RHS columns, each weighted adjoint RHS is reconstructed in that basis with a relative residual check, and the same linear combination is applied to solved unit responses. Contact sensitivity remains the deciding gate, not the tiny volume discrepancy.

## Evidence interpretation

- Existing copied-engine smokes establish arithmetic consistency between implementations that share the same copied equations; they do not certify agreement with the frozen production executable.
- Frozen production baseline comparisons are the acceptance authority for output gates. Preserve failed batch contacts and high-degree native-grid kernel groups as failures.
- Solver residuals only establish algebraic residual quality. Band LU/natural ordering/static condensation fail field/contact agreement and remain diagnostic-only.
- The spectral packet excludes contact terms; its favorable volume correctness and timing do not establish end-to-end acceptance.
- The reported 32 MiB/512 MiB figures are retained/accounted payload bounds, not process peak-memory measurements.
- Raw frequency-bin extensions are discrete/performance probes; they do not establish physical convergence.

## Final independent disposition

Production promotion: do not ship from this audit alone; integrate as a staged implementation behind the existing API and rerun production regression/field/contact gates before changing defaults.** The v6 complex-tensor candidate has a valid frozen build, all 18 headline frozen-array cases pass, and the dedicated eight-case cache matrix passes: contacts-on tests use batch-response caching off (L3/3-objective and L12/2-objective, zero/default forward budget); contacts-off tests use batch-response caching on (L12/3-objective, both tensor layouts, zero/default budgets). The final report correctly separates v5 Born evidence from v6 forward cache checks, distinguishes v2 spectral volume algebra from end-to-end/contact validation, and names batch-contact and L12 native-grid failures as rejected. The spectral table separates compact-basis cold cost from global frame/Gaunt setup. The report build log is clean and `main.pdf` is seven A4 pages. I found no remaining code-level correctness issue in the cache key/lifetime/index handling within the tested immutable one-driver context. The forward cache is limited to repeated angular synthesis/suffix work; workspace prep and representative coefficient gathering still execute. Cache memory figures are payload estimates, and process HWM is not an aggregate limit.

The accepted implementation sequence should remain conditional: retain the equilibrated solver and arbitrary-radius API; integrate semantic angular planning/tiled direct synthesis with strict contact tests first; treat forward angular-field reuse as a separately validated objective option; leave receiver-row response batching disabled for contacts until it has a contact-safe implementation and fallback; defer native-grid defaulting until L12 resolves; keep frequency covariance as a measured standalone candidate until a full solver-to-output path is integrated and benchmarked. Band LU, natural sparse LU, and condensation, the strict architecture control, contacts-on response batching, and L12 native derivatives remain failed/rejected.

# Exact algorithm options for the full native physical kernel

26 October 2026. Read-only algorithmic audit; no option here is implemented or authorized by this note. The target remains the specified damped-contour, windowed vertical measurement and **every** complete-2L angular point on all 179 one-sided native radial nodes. A fast waveform is not a convergence certificate for the local kernel field.

| Priority | Exact option | Why it is promising | Required gate |
|---|---|---|---|
| 1 | Reuse baseline frequency factorizations for kernel unit-receiver responses | Removes the second modal factorization pass for the 52 active bins | Same complex baseline, `q·P(B raw)=2E`, all six pointwise kernels, and factorization-count parity |
| 2 | Bounded global GSH synthesis with Eigen-internal dense products and one-write output | Replaces per-point local degree sums and about 50 full-file updates with batched angular tiles and one final write | All-channel complex and one-sided-interface parity; measured RSS, throughput, and disk capacity |
| 3 | Specialize the **vertical** receiver's adjoint to spheroidal `m=0` | Removes algebraically zero receiver-pole `m=±1` and toroidal adjoint work, particularly backsolves/storage | Compare full weighted adjoint fields and all kernels; retain toroidal **forward** source response |
| 4 | Batch frequency factors at each angular/radial tile | Improves Wigner/FFT reuse and tensor contraction locality | No change to per-frequency weights/order; numeric parity across bins and bounded memory |

## 1. Share the modal solve across baseline and kernel

The saved DSpec v4 L128 probe counts **26,985 factorizations**, exactly `53*(2*128+1) + 52*(2*128+1)`: 53 baseline bins, including the guard, then 52 nonzero-weight kernel bins; `2L+1` counts radial `l=0` and spheroidal/toroidal families for `l>=1`. Its baseline stage is 9.63 s and kernel workspace stage 17.93 s in that sampled probe, with 12.07 s total sparse factorization. The baseline calls `prepareFrequencyWorkspace(..., forwardOnly=true)`; the kernel later calls the same degree/frequency systems with a known energy-adjoint weight. These are repeated numerical matrices, not different physical frequency grids.

The existing `solveForwardAdjointFrequency`/pole-only route can solve forward source and **unit receiver adjoint basis** using a single factorization per `(frequency, degree, family)`; the frozen v4 kernel path already uses this pattern. During the baseline pass, retain or spool only the compact forward and unit-receiver pole responses needed at the 179 radial sides and receiver sample. After the baseline waveform fixes `q` through the exact window/FFT adjoint, combine each stored unit response with its complex per-frequency `q` weight (including the current `conj(fz)` and receiver-basis transform conventions), synthesize fields and contract kernels without refactorizing. This is exact linear reuse because `q` changes right-hand-side coefficients, not the matrix. The 53rd zero-kernel-weight guard needs only its baseline forward solve.

Do **not** infer that the current `BatchResponseCache` alone solves the memory problem: retaining all high-L full modal vectors for all bins can be large. Compact one-sided radial coefficient records can be spooled with source/receiver frames and frequency metadata, then read in bounded tiles. The prior loose six-channel local-order estimate at L1536 is about 10.23 GiB for 52 frequencies ×179 sides on disk, before compression or metadata; benchmark actual representation and I/O. Verification must compare the processed baseline and energy derivative before kernel comparison, because the time window mixes frequency bins. A factorization-count decrease by roughly 52/105 for the active solve families is a potential outcome, not a measured speedup or a promise that total wall time halves.

## 2. Specialize the vertical receiver algebra, but keep source physics

At the receiver pole, the v4 `receiverAtPole` assigns spheroidal vertical component `harmonic(l,m,0,0,0)`, which vanishes for `m≠0`. Its toroidal vertical row is identically zero. With the frozen measurement's only nonzero vertical weight, the receiver adjoint therefore has spheroidal `m=0` support (plus radial `l=0`) and no toroidal adjoint. Current generic basis construction can still solve three receiver displacement directions and carry `m=±1`/toroidal unit responses before multiplying their weights by zero. An exact specialized unit-up RHS can reduce adjoint backsolves, coefficient storage, and angular synthesis. It generally **does not remove toroidal factorizations** from the *kernel* solve: the earthquake moment source excites toroidal forward strain, which can interact with the nonzero spheroidal adjoint in the local material products. For the scalar vertical baseline alone, toroidal forward displacement is zero at the receiver, but the full kernel has a different need. Check the receiver-basis transform, source normalization, and both signed spin channels against the generic path before skipping work.

## 3. Why precontracting frequency before angular synthesis is not free

The local point kernel is a weighted sum over frequencies of bilinear forward/adjoint strains, schematically `K(x)=sum_k w_k Re[epsilon_F(k,x) · C · conjugate(epsilon_A(k,x))]`. Each field is a degree-L harmonic sum in a **different** source/receiver pole frame. Expanding the product first creates cross-degree/order pairs. Even using the small local order support (source `|m|<=2`, vertical adjoint `m=0`), a frequency-precontracted matrix has `O(L²)` coefficient pairs per radial side; evaluating those pairs at every native angular point costs `O(N_angle L²)`, compared with retaining rank-52 frequency factors and synthesizing each field in `O(N_angle * F * L)` before pointwise products. Since physical L≫52, a dense precontraction can be substantially worse in work and storage. Rotating both factors to global coefficients makes a still denser coupling; product-to-harmonic/Gaunt convolution is not a free diagonalization for a pointwise kernel with different pole frames. A favorable low-rank compression would require an independently validated error budget and is not an exact default.

Exact *batching* is useful: within each bounded theta/radial tile, synthesize several frequencies and same-spin components together, then contract and add them in the original bin order. This reuses Wigner rows/matrix products without replacing the 52-term observable. Preserve DC/endpoint factors, the contour-bin taper, and the accepted real contraction; compare against the frozen per-bin sum because reassociation changes rounding.

## 4. Native full-grid synthesis and output schedule

The v2 global-GSH low-L gates establish the coefficient-rotation convention and exact fluid pressure projection on tested solid/fluid interface sides. A full route can choose **symmetric paired theta tiles** from the native `2L+1` Gauss rows, keep the full native `FastFFTSize(4L+1)` longitude row, and synthesize each spin channel on those exact points. GSHTrans's stock `ForBand(L,2,2)` object declares degree `2L` and is refused for `L>=914` by the double Wigner safety check; a derived inverse-only grid may declare actual field degree L while retaining the identical native point set. The 64-row reflected all-spin Wigner matrix is about 2.82 GiB at L1536 and 3.99 GiB at L1827, before coefficient/output/FFT/SEM allocations. Smaller tiles or frequency batches can keep resident memory bounded, at a measurable table-generation cost.

There is an important **math-backend boundary**: cached GSHTrans `TransformKernel::Matrix()` is compiled only with `GSHTRANS_HAVE_BLAS` and directly calls Fortran `dgemm_`; the frozen DSpec direct builds link BLAS for existing solver symbols but do not enable that GSHTrans macro. If the user's no-new-external-BLAS preference applies to the angular route, use the same real Wigner matrix products through **Eigen's internal GEMM** in an isolated adapter, with a checked FFT/longitude stage and reflected-order signs; do not label the library Matrix() path an Eigen-internal implementation. This requires its own low-L all-point complex spin, fluid, radial-l0, and one-sided-interface parity gates, followed by measured high-L native/profile timing and RSS. It is an algorithm option, not a completed feature.

Tile-outer/radial-inner processing can hold one bounded kernel accumulation tile through all 52 frequencies and write each full-grid output row once. It needs the compact coefficient spool from option 1 (or repeated modal solves); the former is preferable to about 52 read/modify/write passes over the enormous final file. At L1827 the native grid is `3655×7350` per radial side: 4.809 billion points across 179 sides, about 179.14 GiB for five float64 moduli or 214.97 GiB for six channels including fluid kappa, before scratch/spool. Disk-capacity, quota, overflow, partial-output, and peak-RSS gates must precede a full run. Angular tiles are an execution schedule, **not** a sampled replacement for the required global grid.

## 5. Degree/tail limits are separate scientific gates

The cached double Wigner recursion refuses degree above 1827; merely raising a CLI cap cannot validate higher coefficients. The saved L1792-vs-L1536 windowed waveform difference is `1.23955e-3`, above the fixed `1e-3` gate, although energy differs by `7.949e-4`. A close 1792→1827 step alone would not prove the omitted tail, given earlier angular oscillation. More importantly, waveform convergence at a distant receiver does not imply **pointwise full-volume kernel** convergence: the radial grid reaches material sides close to source/receiver singular regions, where high-degree evanescent/near-field factors can persist. The complete-2L angular grid exactly resolves the *product of two degree-L truncated fields*; it does not bound the error from omitted degrees. Static-tail extraction, radius-dependent evanescent cutoffs, or source/receiver exclusion would require a mathematical bound and a quantitative error allocation tied to the original observable and local kernel, plus independent high-L validation. They are not authorized silent changes to this full-global request.

# Exact global GSH synthesis on the native complete-2L grid: feasibility audit

26 October 2026. Read-only mathematical/API assessment; no Earth solve, compilation, or production change was made. The requested object is every angular point on the native `GaussLegendreGrid::ForBand(L,2,2.0)` grid at each of the 179 one-sided radial nodes, with the accepted physical kernel and all five material components. Radial-side selection or degree-tail truncation would change that request.

## Decision

An exact coefficient-rotation and global inverse-GSH route is plausible and deserves a **small, measured prototype**, but it is not yet a demonstrated practical full-grid solution. It eliminates the current source-frame coordinate/tangent rotation and independent degree sum at *each output point*. The cached GSHTrans inverse transform still has a dense Legendre stage of order `O(N_frequency N_radial N_spin L^3)`, plus `O(L^2 log L)` FFT work per field. It can save large constants and use contiguous batches; it cannot be advertised as a fast asymptotic spherical harmonic transform. At `L=1536`, output alone is about 126.23 GiB for five float64 components, and one full eight-double point array is 201.97 GiB. Neither can be held under an 8 GiB memory cap. Radial/frequency streaming, measured throughput, and a disk preflight are necessary.

There is a **specific stock-grid blocker**. The cached GSHTrans `GaussLegendreGrid<double,All,All>::ForBand(L,2,2.0)` declares maximum degree `2L`. Its base `SphericalGrid::Impl` calls `WignerDetails::CheckSafeDegree<double>(2L)` even when `WignerValues::Generated()` is chosen. The double recursion limit is about 1827 (the library's `MaxSafeDegree`), so this constructor refuses `L >= 914`, including the current 1024–1536 range. `WignerValues::Stored()` is also infeasible at this size; `TransformKernel::Matrix()` refuses generated values. This is an API/numerics limit, not a disk or thread setting.

A thin derived `SphericalGrid<double,All,All>` can reproduce the **same native points and weights** while declaring only the actual field degree `L`: construct `2L+1` Gauss-Legendre colatitudes and weights by the same `GaussQuad::LegendrePolynomial<double>::GaussQuadrature(2L+1)` and `acos(-x)` mapping used by `GaussLegendreGrid`, set `nPhi=GSHTrans::FastFFTSize(4L+1)`, `nMax=2`, `WignerValues::Generated()`, and `TransformKernel::Loop()`. The protected base constructor accepts arbitrary strictly increasing interior nodes/weights and explicit longitude count; it requires only `nPhi >= 2*declared_lMax+1`. `InverseTransformation(L,n,complex_coefficients,complex_field)` generates Wigner values only through `L`, which is below the 1827 bound for all currently tested degrees. This changes the *declared transform band*, not the native sample set or the requested complete-2L quadrature. It must be checked at a low `L` against `ForBand(L,2,2)` for exact theta/phi/weight order and `FieldSize()`. Calling the derived object itself a native `GaussLegendreGrid::ForBand` would be misleading; the output contract should say identical native complete-2L points/weights with band-L synthesis.

## Rotation and coefficient contract

The frozen DSpec v4 pole path is the useful starting point: `Windowed3DFrequencyWorkspace::prepare(..., poleOnly=true, forwardOnly=false)` skips global `ParamInfo`/all-order nonradial weighted adjoint RHS, but retains reduced source and receiver pole blocks. The forward source has local orders `|m'|<=2`, and the receiver-pole adjoint has `|m'|<=1`; degree zero radial contributions must be included. `poleStrainCoefficients` supplies exactly the six complex spin-strain channels `rr`, horizontal trace (spin 0), radial plus/minus (spins ±1), and horizontal plus/minus (spins ±2). Its `raw` values, rather than the radius-scaled values, enter the accepted pointwise tensor contraction. Frequency/normalization factors already present in the reduced modal blocks must remain unchanged.

The source/receiver local-to-global Cartesian frame in `poleFrame` has columns equal to `R=R_z(lambda) R_y(theta_0)`, where `lambda` is longitude and `theta_0` is geocentric colatitude. In the code, the local harmonic is

`Y^N_{lm}(theta,phi) = sqrt((2l+1)/(4pi)) d^l_{N,m}(theta) exp(+i m phi)`.

For each spin `N` and degree `l`, the candidate coefficient rotation consistent with this phase and the code's tangent factors `c^N=(a-i b)^N` is

`A^N_{l m}(global) = exp(-i m lambda) sum_{m' in local support} d^l_{m',m}(theta_0) A^N_{l m'}(local)`, `-l<=m<=l`.

Here `d` is the **unnormalized** real Wigner small-d, with its first index being the local order `m'`. `GSHTrans::Wigner` returns `sqrt((2l+1)/(4pi))*d`, so a rotation table drawn from that API must divide by this degree-dependent normalization. The sign/index order is pinned at two easy checks: a pure positive z rotation yields `exp(-im lambda)`, and rotating the `l=1,m'=0,N=0` field about y gives the `d^1_{0,m}(theta_0)` row (including the code's `d^1_{0,1}=-sin(theta_0)/sqrt(2)`). This proposed formula is a derivation, **not yet a runtime validation**. In particular the ±spin frame phases and pole conventions need an all-point complex-field gate.

For each channel, fill a `GSHIndices<All>(L,L,N)` array of `grid.CoefficientSize(L,N)` complex entries (zero all unsupported lower degrees/orders). `SphericalGrid::InverseTransformation(L,N,in,out)` then synthesizes one complex field on the full native angular grid; its batched overload accepts `Batch::Contiguous` or explicit `Batch` strides for multiple fields of the same `N`. Use complex output even at spin zero: the contour-frequency strains are complex and should not be forced into the real-field coefficient symmetry. Batch a small number of same-spin channels/radial sides to amortize generated Wigner values; bound the batch by measured resident memory. Rotation tables are static for each source/receiver frame and need only the local `m'` rows over all global `m`, `O(L^2)` values per frame. The four or six requested channels can be streamed instead of held together.

The **strict validation gate** before applying this at physical `L` is: at small degrees including `l=0,1,2` and a moderate `L`, compare every complex forward and adjoint strain channel at *every* native angular point and several radial sides against the accepted frozen pole/tensor synthesis, with both nontrivial source and receiver latitude/longitude. Include polar-near Gauss rows, all signs of `m`, ±1/±2 spin channels, fluid and solid sides, and duplicated interface radii. Compare the subsequent five component pointwise kernels and weighted radial/angular integrals independently. Tolerance should scale with the maximum reference component, with absolute floors for near-zero channels; use the existing cross-route scientific tolerance or tighter, and record max/RMS residuals and the exact point count. A scalar-only or real-projected comparison cannot validate this rotation.

## Cost and storage at the current range

The native grid has `n_theta=2L+1`, `n_phi=FastFFTSize(4L+1)`, ordered theta-major. For 179 sides, the exact lower-level sizes are:

| L | n_theta × n_phi | Points over 179 sides | Five-float64 output |
|---:|---:|---:|---:|
| 1024 | 2049 × 4116 | 1,509,629,436 | 56.24 GiB |
| 1280 | 2561 × 5145 | 2,358,565,755 | 87.86 GiB |
| 1536 | 3073 × 6160 | 3,388,412,720 | 126.23 GiB |

One band-L complex coefficient field has `(L+1)^2-N^2` entries, about 2.36 million or 36 MiB at L=1536. One native angular complex output field is 18,929,680 entries or about 289 MiB. Generated Wigner scratch holds one `(N,theta)` block, roughly `(L+1)^2` doubles or 18 MiB per worker, rather than the immense stored all-theta/all-spin table. However each inverse call regenerates it over all ~3073 theta rows. Batching fields with the same spin is therefore likely important, and the batch count must be measured with RSS.

The rotation step costs `O(N_frequency N_radial N_channel M_local L^2)` complex operations. The inverse Legendre stage costs about `N_frequency N_radial N_channel * n_theta * (L+1)^2` complex coefficient updates, with FFT work `O(N_frequency N_radial N_channel n_theta n_phi log n_phi)`. At L=1536, 52 selected frequencies, 179 sides, and roughly 12 forward/adjoint spin channels, the dense stage alone is on the order of `8e14` complex updates before Wigner generation, tensor products, and I/O. A claimed `~50x` benefit over the current per-point local-order sums is a **hypothesis to benchmark**, not a result or a change in cubic degree scaling.

The output schedule matters as much as the transform. A frequency-outer loop that updates a five-double full-grid accumulation file after each of 52 frequencies can cause roughly 52 passes of read/modify/write over a 126 GiB file (order 13 TiB of traffic at L=1536). A radial-side-outer schedule could accumulate one side (~0.705 GiB for five doubles) over all frequencies and write it once, but it requires either compact coefficient caching/spooling or repeating frequency modal solves. The naive all-frequency/all-side local coefficient cache is itself many GiB (up to tens depending on stored channel representation); it cannot be assumed to fit under 8 GiB. A bounded radial/frequency block with explicit peak-RSS and disk-traffic accounting is required. The final global file must retain all 179 radial sides, native repeated-radius ordering and one-sided interface identities, and all angular values; blocks are an execution schedule, not a sampled replacement.

## Recommended next gate (no implementation in this audit)

1. Construct the declared-band-L derived grid at low L and prove point/weight/order identity to `ForBand(L,2,2)`; verify the custom grid succeeds at L>913 without generating degree-2L Wigner values. Check high-L Gauss node generation and transform initialization cost separately.
2. Rotate reduced pole coefficients with **unnormalized** `d`, synthesize six complex spins through `InverseTransformation`, and require the all-point/channel/tensor equivalence gate above before calling it an exact replacement.
3. Benchmark a representative one-frequency, one-radial-side case at several L with native and instrumented builds, reporting modal solve, coefficient extraction/rotation, Wigner generation plus inverse Legendre/FFT, tensor contraction, RSS, and output throughput. Extrapolate to the full 179-side/52-frequency request only from measured scaling, and require a disk-capacity preflight.
4. Only if the prototype and resource gate pass, integrate a bounded streaming full-output route. Keep angular/degree/radial refinements and the numerical physical convergence decision independent of a successful synthesis optimization. No static-tail subtraction, degree-dependent radial cutoff, selected-side output, or point subsampling is authorized by this analysis.

## Follow-up: exact symmetric theta tiles and BLAS matrix batches

The full `2L+1` theta array need **not** be present in one `SphericalGrid` object for an **inverse-only** calculation. The base constructor checks nonempty, sorted interior theta values and matching weights, but has no lower bound `nTheta>=L+1`. `InverseTransformation` performs a degree-L harmonic synthesis at those requested theta rows; its matrix kernel does not use quadrature weights. Therefore a derived grid with declared degree `L`, full native `nPhi=FastFFTSize(4L+1)`, and a subset of the native `2L+1` Gauss rows evaluates exactly the requested samples. This partial grid would be unsuitable as a degree-L *analysis/forward-transform* quadrature; use it solely for inverse point evaluation. Carry the original full-grid weights into the eventual kernel integral and metadata.

`TransformKernel::Matrix()` plus `WignerValues::Stored()` is valid for a theta tile **only if it is symmetric about the equator**. `SphericalGrid::Impl` constructs `WignerMatrices::Reflected`, whose constructor explicitly checks `abs(theta[i]+theta[nTheta-1-i]-pi) <= 64 eps pi`; it stores nonnegative Fourier orders and reconstructs negative orders by the checked reflection identity. A 64-row tile should contain 32 ordered north rows and their 32 reverse-ordered south mirrors from the *same* full Gauss grid. For `L=1536`, the 3073 native rows partition into 48 such paired tiles plus one equatorial singleton, which is itself symmetric. Each tile carries global row indices so its synthesized rows can be scattered into the correct full-output positions. The native longitudes and theta-major ordering within each row are unchanged. This is exact blocking, not an angular sample reduction.

At `L=1536`, one 64-row, five-upper-index (`N=-2..2`) reflected matrix contains 378,224,448 double values, **2.818 GiB**. A complex coefficient field has 2.36 million entries (~36 MiB); a 64×6160 complex output field is ~6.02 MiB. The inverse matrix path also allocates approximately one output-field-sized complex Fourier stage per batched field (plus smaller order/coefficient scratch and FFT plans). For `c` simultaneous fields, a principal lower-bound budget is `2.818 GiB + c*(36.05+6.02+6.02) MiB`, before modal workspaces, FFT plans, thread-local buffers and kernel accumulation. This is ~3.57 GiB for `c=16`, ~4.32 GiB for `c=32`, and **at least 12.58 GiB for `c=208`** (52 frequencies × four spin-0 channels). Thus the suggested all-frequency/four-channel batch does not fit the previously used 8 GiB cap, although a machine with 22 GiB genuinely available might permit it after measured headroom. Batches of 4–8 frequencies times same-spin channels, or `c=16/32`, are the safer initial measurement. Tensor contraction requires all spins for each frequency; retain only the small frequency chunk's forward/adjoint fields, contract it into a roughly 15 MiB five-double kernel accumulator for one 64-row radial tile, then release fields and proceed. The table is retained across all chunks and radial sides for that tile.

This matrix route is **not available in the frozen v4 binaries** merely because they link `-lblas`: their direct `g++` commands do not define `GSHTRANS_HAVE_BLAS`, under which `TransformKernel::Matrix()` and its `dgemm_` calls are compiled. An isolated prototype must add the macro to all relevant translation units and link a verified compatible LP64 BLAS. The cached CMake configuration found OpenBLAS, but its settings do not propagate automatically into these direct commands. The GSHTrans matrix implementation explicitly uses real `dgemm_` on the real/imaginary pairs, not Eigen's existing tensor GEMM backend. The library warns about re-entering some threaded OpenBLAS builds inside OpenMP; begin with one application/BLAS thread and measure before changing thread policy.

The tile schedule now has a concrete I/O tradeoff. A **tile-outer, radial-side-inner** order constructs the 2.818 GiB Wigner matrix once per tile and reuses it across 179 sides and all frequencies; it accumulates and writes every requested output row once, avoiding roughly 52 full-file read/modify/write passes. To prevent repeating the modal solve for every tile, it needs a compact spool of the pole-frame coefficients for all frequencies and radial sides. A loose six-channel, local-order `(5 forward +3 adjoint)` complex representation at `L=1536, Nr=179, F=52` is about **10.23 GiB** on disk before metadata; rereading it for 49 theta tiles is order **0.5 TiB**, much less than the repeated full-output traffic but still measurable. Channel-specific sparse packing can reduce this; the exact modal/strain coefficient representation and one-sided radial identity must be audited. A radial-side-outer order instead repeats the 49 expensive tile-table constructions for each of 179 sides, unless tables are externally cached. Neither option has a measured wall time. Batch efficiency and table construction time should be profiled on one tile and one side before extrapolating to the full materialization.

Additional exactness gates for this blocked form: compare tile grid theta/weights/phi bitwise or within documented Gauss-rounding tolerance to a low-L full `ForBand(L,2,2)` grid; test one 64-row paired tile, the equatorial singleton, and nonconsecutive global-row scatter; compare `Matrix()` against `Loop()` with the same complex coefficients at low L; then apply the earlier all-point forward/adjoint/tensor gate. Retain the full-grid quadrature weights in the final integration, and treat output floating-point summation order as a toleranced numerical difference rather than bitwise identity.

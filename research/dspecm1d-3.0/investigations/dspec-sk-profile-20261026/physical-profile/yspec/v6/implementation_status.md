## V5 bounded-I/O follow-up

- 2026-10-26: Created v5 as an isolated copy of the frozen v4 adapter and build artifacts. V4 source, binaries, and checkpoint manifest remain untouched. V5 changes are limited to reducing sampled-kernel scratch/output residency and documenting the new angle-major binary layout; numerical runs are not authorized in this implementation phase.
- 2026-10-26: Replaced the v4 whole-file mmap accumulator with a POSIX positioned-I/O scratch file. The v5 accumulator exposes bounded range reads/writes, synchronizes explicitly, and intentionally retains scratch after exceptions; scratch cleanup is now an explicit post-output-success action. The working buffers will be limited to one angular block. Integration into the frequency and final-transform loops is pending.
- 2026-10-26: Added an exclusive-created positioned-I/O output writer with checked file-size bounds, short-write/EINTR handling, explicit output fsync, and failure-preserving partial files. Both scratch and output now avoid process mappings; the frequency update and output conversion loops still need conversion to angle-major bounded blocks.
- 2026-10-26: Changed streamed frequency accumulation to read, update, and write one existing 64-place angular block at a time in `[place][node][elastic channel]` order. Each active frequency preserves the original angular-block iteration and local contraction order; the per-block I/O is now named separately in the profile. The former frequency-wide mmap flush/release stage was removed.
- 2026-10-26: Converted final Love output blockwise to `[angle][node][A,C,F,L,N]` float64 order. The adapter caches only per-node material values and transforms at most 64 angles at once; scratch and output have explicit fsync stages, and scratch deletion happens only after output fsync succeeds. Failure leaves the scratch and any partial output intact. Updated API documentation and JSON metadata to identify the v5 binary layout and coordinate-only angular grid.
- 2026-10-26: Extended the pre-allocation resident-memory estimate to count both the local angular contraction tile and its scratch read-modify-write buffer, the simultaneous 8-channel plus 5-channel output transform block, and the per-node material cache. The disk preflight remains scratch plus final output (13 doubles per native radial-angle point). Numerical execution remains pending parent validation.
- 2026-10-26: Added checked `size_t` scratch-value and `off_t` file-length arithmetic before creating the accumulator/output, with bounded range checks on every positioned read/write. The remaining implementation is compile validation and a source-level path audit; no YSpec run is made here.
- 2026-10-26: Split per-block scratch reads, accumulation arithmetic, and writes into distinct named profile scopes. Final conversion likewise has separate scratch-read, Love-transform, output-write, output-fsync, scratch-fsync, and success-cleanup stages.
- 2026-10-26: Corrected the geometry preflight to account for the 32-byte `KernelPlace` plus 40-byte `PointGeometry`, rounded to 80 bytes per angle. The adapter now moves the generated place vector into the kernel sampling instead of keeping a duplicate full angular array during the API call.
